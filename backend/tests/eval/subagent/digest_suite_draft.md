# 「通读消化类」套件（digest）设计草案

> 状态：**草案，待评审**。未冻结前，本文所有规模数字均为设计目标，不是结果；
> 冻结以单独的 commit 为准（任务文本、KeyFact、语料、expected_files 一并入库）。
> 既有 core / large 套件的任务、门槛、评分口径**一律不动**。

## 1. 目的与假设

两轮全量对照已确认：现有任务规模下「避免的摄入」（2–5k token）不显著大于
委派固定开销（tool_search / ticket / 回传 / 核对轮次），**隔离收益没有出现
空间**——两种触发口径都由此 No-go。本套件专门构造相反的量级关系，检验：

**假设 H**：当任务要求把 ≥ 40k 字符（≈15k token 以上）的原文摄入主上下文、
且答案无法被 grep 收窄时，若 B 臂委派，主上下文峰值相对 A 臂可降 ≥ 50%。

## 2. 任务形态（建议 3 个，可裁至 2）

共同点：答案 = 跨来源的**交叉/负向判断**（不一致、矛盾、缺失），单侧文本
（只读规格或只读代码）得不出答案，grep 找不到「差异」本身的关键词。

| 任务 | 输入概述 | 为什么必须通读 | 预期摄入（A 臂） |
| --- | --- | --- | --- |
| D01 specs↔实现 不一致清单 | 「对照 specs/ 与实现代码，列出规格条款与代码行为不符的全部位置（给出规格文件、代码位置、差异）」 | 不一致是跨源语义比对；差异点无共同关键词可 grep | specs 8 份 + 代码 ~10 文件 ≈ 50–70k 字符 |
| D02 specs 内部矛盾条款 | 「通读 specs/ 全部文档，列出互相矛盾的要求条款及双方出处」 | 矛盾检测必须完整阅读；无检索锚点 | specs 全量 ≈ 100k 字符 |
| D03 横切契约矩阵 | 「按模块列出『重试/退避』契约的 specs 要求 vs 实现现状，指出未兑现模块」 | 负向证明：要证明某模块『没有重试』必须读完该模块 | specs 章节 + 全部模块 ≈ 60–80k 字符 |

（D03 可选。若只保留 D01+D02，语料复用同一份 specs/，工作量几乎不变。）

## 3. 语料设计（新增 `specs/` 包）

- 位置：夹具仓库新增顶层目录 `specs/`（**不动** `src/` `docs/` `tests/` 现有
  结构，避免触碰 L01–L09 的标准答案与守卫测试）。
- 规模：**18–22 份文档，每份 4–6k 字符，合计 ≈ 100–120k 字符**；内容为
  「模块契约规格」「横切政策规格（错误映射 / 重试 / 配置）」等类真实工程
  项目的规格文档。
- 植入事实（确定性、护栏测试锁定）：
  - D01：**8 处**规格与实现不符（如规格声称结算失败自动重试 3 次、实际
    `confirm_order` 无重试）；
  - D02：**4 处**文档间互相矛盾条款；
  - D03：重试契约矩阵（每模块一项：要求 / 现状 / 是否缺失），部分模块
    在 specs 中被要求而实现没有。
- 约束：specs 文本**不得**引入现有守卫测试的敏感记号（`lockout_window`、
  4 个 Deprecated 函数名、`ENABLE_LEGACY_EXPORT`、docs-only 环境变量、
  `= connect(` 等）；不得新增 `tests/test_*.py`；全量离线回归必须全绿。

## 4. 摄入量论证（为什么 50% 门槛「有可能」过）

已知实测（全量 large）：

- B 臂主峰值地板估计 ≈ **6–9k**（基础提示词 + ticket + 回传 + 收尾）；
- 现有任务 A 臂峰值 ≈ 5–11k（可被 grep 收窄，摄入不足）。

据此：要让降幅 ≥ 50%，A 峰值需 ≥ 2×B ≈ **16–18k**；按 2–3 字符/token
折算需真实摄入 **≥ 40–60k 字符**。§3 语料把「必须读」的量拉到
**90–120k 字符**，留出两层余量：

1. 压缩余量：即便主上下文维护把峰值压掉 40%，A 峰值仍 ≈ 18–25k；
2. 剪枝余量：即便 grep 帮 A 少读 30%，摄入仍 ≥ 60k 字符。

这同时构成设计自检：**若机制试跑显示 A 峰值不随语料增长（压缩封顶）或
B 始终不委派，本套件无法检验假设**——此时如实归档，回到设计桌，而不是
调门槛。

## 5. 委派触发预期与风险

- 现口径「先探后决」的措辞覆盖「通读大量文件 / 跨模块综合」；预期 B 在
  探测到 specs/ 规模后委派。**风险 1：模型仍坚持自办**（large 上已有先例：
  L01/L04 考察后自办）。若发生：这本身是真实结论（「现行政策在消化类上
  也不兑现隔离」），照实归档。预登记的应急路径：以「优先委派」形态文案
  （全文留档于 `38f6c62`）**另跑一轮独立标注的配置对照**，不修改任务与
  门槛。
- **风险 2：子代理效率**（L02 r1 出现 4 遍重复通读 + 预算收口）。消化类
  任务上子代理 token 可能失控，成本比破 1.3。观察指标：子代理工具调用数、
  重复读取率、预算告警次数；若发生，结论将是「隔离成立但成本需优化」的
  分域结论，照实报告。
- **风险 3：A 臂压缩封顶峰值**。以 §4 余量 + 机制试跑验证；若试跑显示
  封顶，扩语料至 150k 字符（在设计校准范围内，记录在冻结说明里）。

## 6. 门槛与判定

- **沿用全局三门槛**（README 判定规则 1/2/3），数字不变；digest 作为第三
  套件**单独跑批、单独报告、单独归档**（`reports/`）。
- 附加诊断字段（不进门槛）：委派发生率、回传字符、子代理 token、每任务
  A/B 实际读取数（进校准表）。

## 7. 流程（预登记纪律）

1. **评审本草案**（本节）→ 定稿；
2. 实现：specs 语料 + 护栏测试 + tasks.py（`SUITES` 加 `digest`，新分类
   `digest_synthesis`）+ 计数测试更新 + README 改「三套件」+ docs 记录；
3. 可选**机制试跑**（1 题 × 1 轮 × 2 臂，≈$0.05，仅验证「峰值随语料增长 /
   是否触发委派」，数据标注为设计校准、不进正式对比）；
4. **冻结 commit**（任务文本、KeyFact、语料、expected_files 全部入库）；
5. 正式跑批：`--suite digest --runs 3`，同模型同价格（deepseek-v4-flash，
   0.14/0.28）；报告归档；
6. 更新 docs：隔离假设「成立 / 不成立 / 机制未触发」三态结论。

## 8. 工作量与预算

- 实现：specs 语料撰写（≈100–120k 字符）+ 3 任务 + 护栏/测试改造，一次性；
- 机制试跑：2 runs ≈ $0.05、~3 分钟；
- 正式跑批：18 runs（3 题 × 3 轮 × 2 臂），预计 **$0.3–1.5、20–40 分钟**
  （重读任务单 run 更慢，子代理失控时上限浮动）。

## 9. 明确不做

- 不修改 core / large 既有任务、标准答案与门槛数字；
- 不为「让 B 赢」调整任何门槛或评分口径；
- 不在正式报告里混用两轮对照数据（各报告的提示词口径与冻结提交必须注明）。
